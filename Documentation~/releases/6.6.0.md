# Lemmings 6.6.0

Lemmings 6.6 cuts the token cost of the pipeline. The workflow does not change. What changes is how much each agent reads and re-reads. The measured cause on a real Unity project (one week, about 6,250 requests): 87% of the estimated cost was subagents, about 94% of it cache read and write, because every request re-reads the whole context and writers ended at 400–760k tokens after 160–390 requests. Three quarters of the agents were `general-purpose`, outside Lemmings, with no pinned model and no limit.

The package rule "no budgets or hooks" is relaxed to "only with measured benefit and in the lightest form". Everything below is a definition field, a line in `SKILL.md`, or an advisory printout. There are still no hooks, no state machine, and nothing that blocks.

## New

- **Turn budget for native agents.** An agent may set `maxTurns`; otherwise the role default applies (explorer 25, reviewer 40, worker 80). `agents sync` writes it into the Claude Code agent file. `SKILL.md` treats an agent that stops at its budget, or whose context passed about 300k tokens, as blocked: a fresh agent gets the brief plus a short handoff, and the old session is never resumed.
- **`instructions` on an agent.** Up to 600 characters appended to the role prompt, for a narrow specialty (for example a Haiku explorer that runs scripts and returns digests). It guides behavior; the role still decides the tools. No new role was added, and no `tools` override either, until a real need appears.
- **Delegation rule.** `SKILL.md` says to delegate only to `lemmings-*` agents, never to `general-purpose`, `Explore`, or `Plan` for repository work, and never to override the model per call. Routine work goes to the cheapest agent that can do it, and large structured data is read by a script or such an agent.
- **Structured, short briefs.** Fixed format: `Task`, `Agent`, `Goal`, `Acceptance` (at most 5), `Owned paths`, `Checks`, `Context` (at most 10 `path#symbol: why` items), `Stop`. `Task:` is required so usage can be tied to the task. Workers return a report of about 1.5 KB, explorers a condensed finding, reviewers start from `git diff --stat`, and no agent polls or loops while waiting.
- **`lemmings brief check|template`.** Prints size and shape warnings (missing sections, over `contextPolicy.targetBytes` default 4096 or `ceilingBytes` default 16384, too many criteria or context items, pasted code, polling). It is advice for the manager and never fails. `tasks add` returns the same `briefWarnings`.
- **A journal of live work only.** `tasks update <ID> --status Done --commit <sha>` removes the row and the task file and appends one line to `ARCHIVE.md`. `Done` now requires a commit. Archived ids still satisfy dependencies. `tasks archive` sweeps rows already marked `Done` in existing journals.
- **`lemmings doctor` warns about dead settings.** Keys of `.agents/lemmings.json` that this version does not read (such as `invocationBudgets` or `orchestration`) are listed as warnings, so a stale config no longer looks like active limits.
- **`lemmings-telemetry usage`.** Offline report over Claude Code transcripts: estimated cost, requests, and peak context per task (from the `Task:` line of the brief) and per agent type, plus the share of agents outside `lemmings-*`. `--since` takes the weekly limit reset. Prices are an editable estimate.

## Upgrade

- Run `lemmings agents sync` to add `maxTurns` to native agent files, and `lemmings tasks archive` once to move finished rows out of an existing journal.
- Remove old keys that `doctor` lists as unread from `.agents/lemmings.json`. `contextPolicy` is read again, but only as the advisory brief sizes `targetBytes` and `ceilingBytes`.
- Put `Task: <ID>` at the top of briefs.
