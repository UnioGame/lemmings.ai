# Lemmings 6.0.0

Lemmings 6.0 keeps the complete workflow available when Python or the optional runtime is unavailable, while making runtime execution easier to resume, measure, and repair. The runtime now uses schema v5 and a high-level `flow` interface for Simple, Standard, and Strict work.

## Highlights

- **Skill-only remains a first-class path.** Discover, Plan, Refine, Implement, and Verify work without Python, runtime artifacts, trusted receipts, or runtime-compatible hosts. Missing dependencies never block task delivery before runtime activation.
- **One high-level runtime flow.** `flow start`, `advance`, `submit`, `replan`, `finish`, and `status` drive deterministic Task and Phase transitions and return explicit actions for the manager.
- **Safer default accounting.** New runtime owners use `invocation-v1`. `host-v1` is available only when every executing host declares trusted usage accounting before the first invocation.
- **Automatic bounded repair.** P0-P2 findings open repair, P3 findings remain follow-ups, and repaired candidates receive delta review unless the review basis changed.
- **Strict orchestration support.** Phase briefs define task dependencies, ownership, workspace policy, reviewer routes, integration, and final phase validation. Dependency-ready writers run in complete waves.
- **Explicit migration.** `migrate propose` creates a reviewable v4-to-v5 proposal, and `migrate apply` requires its digest before writing verified v5 copies. Original artifacts, IDs, evidence, accounting mode, budgets, and locks are preserved.

## Runtime behavior

Runtime owners now bind invocations to owner kind, ID, and revision. Repeated commands resume the saved operation without creating another invocation or spending the budget twice. Review subjects cover candidates, task plans, and phase gates. Integration verifies the exact candidate ancestry, declared checks, final HEAD, and workspace disposition.

The default `invocation-v1` mode counts actual role invocations across retry, repair, recovery, and replan. A `host-v1` brief must freeze a capability snapshot with `usageAccounting=true`; unsupported hosts are rejected before runtime state is created. Once runtime work is active, disappearing dependencies remain an explicit error so evidence is not silently abandoned.

## Skill-only behavior

The self-contained skill uses the same acceptance, review, sandbox, safety, and model-routing requirements without importing schema-v5 code. Standard work supports worker, independent review, repair, and verification. Strict work supports isolated writers, dependency waves, and integration validation through the capabilities available on the host.

If runtime status is unknown, the manager may run one bounded doctor check. When Python, the bundle, or a compatible runtime is absent, the manager offers installation once and continues skill-only if installation is declined. Inactive hooks exit before searching for Python.

## Upgrade notes

- Package and plugin version: `6.0.0`.
- Runtime Task, Phase, and Review artifacts use schema v5.
- Existing v4 runtime artifacts are not changed in place. Use `migrate propose` and `migrate apply` to create v5 copies.
- An active invocation blocks migration.
- Migration does not unlock exhausted `host-v1` accounting or change the frozen accounting mode.
- Skill-only notes and conversation state require no migration.
- Restart or reload the host after updating the Codex or Claude plugin so it reads the new skill and role definitions.
