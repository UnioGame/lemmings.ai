# L5 implementation contract

This file is a hashed Task working-set reference. Changing it invalidates the plan review. Phase contracts reference the same digest. No public API may be independently changed without manager integration.

## Delivery topology

Manager integration checkout is an isolated package Git worktree, not the primary game repository. Wave 1: A owns workspace.py + test_workspace_safety.py; B owns discovery.py + profiles.py + test_discovery.py + test_profiles.py. Wave 2, after the whole first wave is complete: C owns rules.py + rules/** + test_rules.py; D owns runners.py + test_runners.py. Each worker has a distinct Task, branch and worktree at one pinned phase integration SHA, ownedPaths restricted to its listed files and parallelReason independent_paths. No worker writes CLI/contracts/installers/docs. Manager owns those seams and integrates only complete waves. All worker tasks depend on their recorded phase baseline and accepted parent plan. Maximum two worker invocations concurrently. Candidate review covers the assembled immutable range.

## Discovery and profiles

APIs accept pathlib.Path repo/home and JSON dictionaries; home defaults to user home. No dependency on CLI or other new module is necessary except profiles importing discovery. Export scan_providers(repo, *, offline=False, home=None, host_catalog=None), probe_route(route, *, home=None), inspect_profiles(repo, *, home=None), build_profile_proposal(repo,name,routes,*,home=None), apply_profile_proposal(repo,proposal,confirmation,*,home=None), use_profile(repo,name,*,home=None), resolve_profile(repo,name=None,*,home=None,host_catalog=None).

scan returns {schemaVersion:4, scannedAt:UTC, providers:[], routes:[], diagnostics:[]}. Provider: {providerId,source,authConfigured:bool,catalogStatus:current|stale|unavailable}. Route: {hostId,providerId,modelId,variantId?,executor:native|codex|opencode,profileName?,protocol:responses|chat-completions|messages|unknown,configured:bool,catalogued:bool,compatible:bool,authConfigured:bool,probed:bool,quotaGroup?,source}. Optional metadata is allowlisted; no raw config, credentials, headers, prompts, endpoint query strings or exception bodies in snapshots. A configured model is not necessarily catalogued, compatible or executable. Unknown endpoint protocols stay unknown. Endpoint public catalog cannot prove account access. Discovery never runs inference; probe is explicitly selected route only. OpenCode/Go catalog routes with non-Responses protocols require OpenCode executor, never Codex. Existing normalize_catalog is a separate legacy explicit-catalog interface; new commands do not pass discovery shapes to it.

Project manual inputs are .agents/lemmings.json modelRoutes and optional profiles {name:{roleRoutes:{worker:[],reviewer:[],explorer:[]}}}. Personal inputs are ~/.lemmings/profiles.json with same profiles shape and optional activeProfile. Generated ~/.lemmings/state.json contains inventory, profiles and selections keyed by canonical repo. Route objects use the same fields as discovery routes, with hostId required for executor selection. Role chains are ordered and explicit. build_profile_proposal returns {schemaVersion:4,name,roleRoutes,inventoryDigest,manualDigest,proposalDigest}; apply verifies digest, unchanged input inventory/manual sources, and confirmation equals proposalDigest. It saves generated profile only. use selects existing name for future tasks. resolve returns {schemaVersion:4,name,roleRoutes,sources,digest}; sources explain per-role project manual > personal manual > explicitly selected generated > current-host default. CLI/task explicit assignment is applied above this snapshot. No name means active selection if present. Empty routes mean current host defaults, not guessed provider IDs. inspect returns available names, origins and selection; no mutation.

## Frozen task and adapters

Task effectiveConfig is optional v4 extension: {schemaVersion:4,profile:{...resolve snapshot},rules:{projects:[],ruleRefs:[],digest},digest}. Assigned Task models and approved recovery chains remain execution authority. Freeze on first invocation; subsequent invocations and results use this effectiveConfig instead of live profile preferences. Rule references {ref,purpose,contentHash} join the existing <=12 context references, not full rule text. Rule changes invalidate the frozen digest; unrelated preference changes affect only new tasks. No inventory or credentials in Task.

D exports build_launch(repo,invocation,route)->dict and run_invocation(repo,invocation,route,*,native_bridge=None,cancelled=None)->AgentResult. Launch {executor,argv,env,stdin,readOnly,capabilities}; ephemeral env config is permitted, no logging it. native_bridge is an injected callable, not an API client; absent bridge returns dispatch-required with saved invocation metadata for the host manager. Codex subprocess uses documented exec/profile flags and Responses only; OpenCode uses documented run/model/agent flags and per-invocation permissions. Never --yolo/full bypass, continue/resume/session history, implicit model substitutions, nested task tools or arbitrary plugins. Read-only roles deny edit, bash mutation and external side effects. If restrictions cannot be enforced, fail unsupported-capability; do not claim sandbox containment from prompt text. Worker owns only assigned paths; integration still rejects out-of-scope diffs. Native capabilities are explicitly supplied by bridge contract. Adapter must preserve existing invocation/result IDs and validation, bounded diagnostic output, exact outcome status. CLI controls saved invocation acceptance; launch success never accepts candidate.

External invocation lifecycle: atomic per-workspace run lock with invocationId, pid, start token, status, route identity; no new writer until prior process termination confirmed. Retain ambiguous/stale locks for manager inspection, never clear on PID reuse assumptions. On cancellation/timeout terminate owned process group/tree, wait, mark cancelled only after confirmed exit; otherwise blocked with process record retained. No retries or fallback in runner: manager records next approved route and creates fresh invocation. Tests use injected subprocess/bridge and offline fake executables, not subscriptions. Route quotaGroup is accounting metadata only; distinct model identities on same quota do not imply extra capacity. If two reviewers unavailable, record single policy + cross-review-unavailable.

## Workspaces

A exports prepare_workspace(repo, *, task_path,destination,branch,expected_revision,approval); release/remove accept task_path and optional task_revision. Once an entry has been activated, missing canonical Task blocks release/removal; legacy boolean evidence is never authority. Unactivated managed idle entries can be inspected but not removed without explicit canonical lifecycle. Task workspace records exact repo root, backend, base SHA, destination, branch, estimate and approval before prepare. Validate provided arguments match the record. package-worktree requires package's own Git root; full code-worktree estimates entire chosen repository. Reject primary managed registration/claim, paths outside intended root, symlink aliases, non-Git and foreign worktrees, dirty/unmerged/ongoing Git operations, invocation/lease/process owners. Resolve relative git --git-path against workspace cwd.

All claim paths use same safety conditions. Registry mutations use CAS lock. Prepare reserves before git worktree add; failure records quarantine, never destructive rollback. No --force/-B/reset/clean/prune. Process records use {pid,invocationId,status,startToken?}; unknown/live or unverifiable records block claim/release/remove even if OS reports dead PID; manager must reconcile recorded completion. activeInvocationId/leases nonempty always block. Release/removal require matching Task id, workspace id, Integrated state, canonical revision, candidate ancestry or explicit verified candidate-to-merge mapping, passing declared commands at close.mergeCommit and actual commit existence. Blocked/Repair/Cancelled never imply permission to delete. User/unknown/dirty/project/validation workspaces are preserved. Pool eviction uses the same evidence, no synthetic Integrated state. Keep 2 idle/10GiB; >10GiB provisioning requires recorded approval. Independent caches, ports and editor resources; no mutable cache sharing.

## Installer and optional rules

Installer defaults to repository root as generic project; optional --project must exist within repo, with technology detection optional. No SDK required. Merge recursively: new defaults fill missing fields; all existing v4 values including manual modelRoutes/custom fields win, then update owned distributionVersion/tooling location. Reject unsupported schemas. Preserve existing role model/effort overrides while refreshing owned instructions. Stage + rollback all owned paths; test injected failures at skill/agents/config. Busy detection includes activeInvocationId and process records. Existing active root bundle will not be replaced by this delivery.

C exports resolve_rules(repo,paths=None,technologies=None,platforms=None)->{projects,ruleRefs,digest}. Manifest specifies IDs, filenames and detection. Paths determine nearest project roots including monorepos; do not recurse generated/cache/dependency trees. Explicit technologies/platforms override detection; platform target is task input, not host OS. Seven packs unity/unreal/godot/defold/flutter/phaser/pixijs plus platforms. Preserve authored assets/metadata, lifecycle/resource ownership, targeted validation, version distinctions, bounded diagnostics/token economy. Rules must include concrete role guidance and game-specific constraints, not placeholders. No engine install/test framework migration/global asset scan. Direct dependency/import/CDN is evidence; transitive lockfile is not.

## Acceptance and validation map

- A: tests/test_workspace_safety.py; active/blocked/cancelled/forged integrated cleanup, primary claim, relative Git operation, package root/estimate, CAS/prepare failures, process/lease retention, pool evidence. Existing workspace fixtures updated by manager if stricter API rejects unsafe calls.

- C: tests/test_rules.py; all seven project types, direct vs transitive dependencies, task root/monorepo, explicit overrides, generated excludes, deterministic hashes and pack substance.
- D: tests/test_runners.py; all three adapters, protocol/capability rejection, role restrictions, real fake-process exit/cancel/timeout, two-writer lock, bounded failure diagnostics, no resume/fallback, result identity.
- Manager: tests/test_zero_config.py + tests/test_effective_config.py + tests/test_cli_extensions.py; generic install/doctor, v4 preservation/rollback, manual override roles, effective snapshot freeze and reference cap, CLI help and documented commands, integration evidence output.
- Complete: python -B -m unittest discover -s tests; git diff --check; skill-creator quick_validate.py skills/lemmings; parse package.json and local Markdown links; fresh bounded forward-test of skill for simple non-game, Unity isolation, Go profiles. Independent immutable candidate review; integration validate at recorded commit. No paid model probes required for offline suite; report that live provider execution is not validated unless explicitly run.
