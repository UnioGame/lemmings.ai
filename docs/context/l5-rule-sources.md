# Rule-pack source anchors

Primary documentation opened 2026-09-10. Select documentation matching the project's pinned version, never upgrade to the current documentation version automatically.

- Unity: https://docs.unity3d.com/Manual/AssetMetadata.html — meta files preserve unique asset identity; moves/renames require paired metadata. Agent rules add narrow asset inspection, lifecycle/allocations, asmdef ownership and isolated Library/editor directories.
- Unreal: https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine — OFPA external actor files are authored content, not a disposable cache. Agent rules add module/reflection/Blueprint compatibility, binary ownership and bounded UBT/asset evidence; packaged plugin Binaries may be required.
- Godot: https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html — distinguish generated .godot/.import directories from authored .uid and per-asset .import sidecars. Agent rules add pinned major/C# version, signals/NodePath and visual-vs-headless validation.
- Defold: https://defold.com/manuals/application-lifecycle/ — component Lua lifecycle, update and messages are ordered. Agent rules add collection/resource ownership, URL references, atlases, Bob version and native extension target validation.
- Flutter: https://docs.flutter.dev/perf/best-practices — limit unnecessary builds and expensive visual operations. Agent rules add actual Flutter SDK detection, existing state architecture/dispose/keys/semantics, targeted analyze/widget checks, golden changes explicit; Flame only when directly present.
- Phaser: https://docs.phaser.io/phaser/concepts/scenes — scene lifecycle includes shutdown, restart and destruction. Agent rules add listener/timer/tween ownership, shared textures, direct version detection, bounded browser input/resize/loading checks and independent dev ports.
- PixiJS: https://pixijs.com/8.x/guides/concepts/garbage-collection — explicit graphics resource destruction/unload and automatic texture collection affect GPU memory. Agent rules add pinned API version, async v8 Application.init, ticker/subscription/mount/resize/DPR ownership; never infer scenes or physics; preserve shared textures.

Platform pack: web memory/assets/renderer/context loss, input/audio/fullscreen gesture and embed restrictions where targeted; mobile lifecycle/pause/resource budgets/permissions/signing under existing build scripts; desktop window/input/display/resources. Publishing SDK behavior follows task target and checked-in integration, not host OS. Profile before optimizing and record scenario/device/metric. No new engine SDK/test framework/build system by default.

All packs must contain concise manager/worker/reviewer-specific guidance, ownership/conflict boundaries, targeted validation and agent context exclusions. Do not duplicate core routing/mode/CAS policy or paste upstream documentation. Read only selected packs within the existing12refs/16KiB context budget.

Resolver packaging seam: use bundle.skill_root(repo), which prefers a target repository installation and otherwise the runtime-adjacent source package. Rule refs must resolve inside the target repo; source-package and installed paths differ. Tests for other temporary projects should copy the minimal shipped rule bundle into .agents/skills/lemmings rather than return nonexistent refs to the outer source tree. If a selected pack exists only outside the target repo, explain that local installation is needed before frozen dispatch; never persist absolute external refs. Generic projects with no selected packs remain usable.

Detection detail: a distribution package.json containing only a Unity compatibility field (as Lemmings itself does) is not sufficient Unity project evidence. Use actual project markers or an explicit technology override for a standalone UPM package. Normalize the common pixi.js spelling to manifest ID pixijs. Keep inspection bounded and explain when insufficient task-path evidence needs an explicit choice.
